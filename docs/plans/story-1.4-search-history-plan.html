IMPLEMENTATION PLAN - STORY 1.4 ONLY

Search history for quick access

Focusing the search field reveals the last 5 successfully-loaded stocks under a Recent heading. Clicking one loads its card immediately, without a trip through the preview list.

Interview decisions

Opening

Dropdown opens on focus. Matches on top, Recent stacked below.

Row shape

A recent row is symbol + company name, identical to a match row.

Controls

Recent label only. No clear-all, no per-row remove, no keyboard nav.

What counts as a search

Recorded only when a stock card loads successfully.

Storage

{ items: [{ symbol, companyName }] } under diamante.searchHistory.v1, capped at 5 on write.

Selecting a recent row

Fills the input with the symbol, so the debounced preview refetch is suppressed for that query.

Scope

Included

  • Recent list revealed on focus, most recent first.
  • Click a recent row to load the card directly.
  • Cap of 5 entries, applied at write.
  • Symbols already visible in Matches are filtered out of Recent.
  • localStorage save and restore.

Excluded

  • Clear-all and per-row remove controls.
  • Keyboard navigation of the dropdown.
  • Timestamps or "searched N minutes ago".
  • Syncing history across devices.

Refactor first

useWatchlist owns ~40 lines of localStorage parse/validate/persist code. A second hook copying it breaches the 5% jscpd budget, so extract before adding.

  • src/utils/guards.ts - isRecord, isFiniteNumber.

  • src/hooks/usePersistedList.ts - usePersistedList<T>(key, isValid) owning parse, shape check, row validation, corrupt-storage fallback and the persist effect.
  • useWatchlist shrinks to its own row guard plus isWatched / upsert / remove.

Acceptance scenarios

Scenario: Recently searched stocks appear in history
  Given user has searched for multiple stocks
  When they focus the search field
  Then a list of recently searched stocks appears below the search field
  And the most recent searches appear at the top of the list

Scenario: User selects stock from search history and sees card
  Given user has previously searched for a stock
  When they click that stock in the search history
  Then the stock card is displayed immediately with all detailed metrics
  And the preview list is not shown

Scenario: Search history is limited to recent searches
  Given user has searched for many stocks
  When they view their search history
  Then only the most recent 5 searches are displayed
